# Coding Assertions

The checks that must pass for code to count as done. Minimal, run after every change.

> **State:** no gate runs yet. The repository has no `package.json` and no Turborepo pipeline — see `aidd_docs/INSTALL.md` install steps 1 and 5. The commands below are the intended gates; verify each one exists before relying on it, and refresh this file once the pipeline is wired.

## Before commit

The fast gate.

| Order | Command | Checks |
| ----- | ------- | ------ |
| 1 | `pnpm turbo lint` | lint across every workspace |
| 2 | `pnpm turbo typecheck` | TypeScript — the main guard, MV3 surfaces are thinly typed |
| 3 | `pnpm turbo test` | Vitest units |

## Before push

The heavier gate.

| Order | Command | Checks |
| ----- | ------- | ------ |
| 1 | `pnpm turbo build` | extension build plus the SDK bundle |
| 2 | `pnpm turbo e2e` | Playwright against the unpacked extension |

## Project-specific gates

- A change to `packages/contract` invalidates both consumers. Build and e2e are mandatory, unit tests alone prove nothing.
- A change to the MV3 permission set requires a full build: the manifest is generated by WXT and permission errors surface at load time, not at typecheck.
- `chrome.debugger` paths cannot be asserted by unit tests. They need the e2e run with a real attached browser.

## Behavior

If a fix is needed, spawn one agent per failing assertion (typecheck / tests / lint) rather than one agent for the whole gate.
